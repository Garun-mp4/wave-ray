# Go backend migration status

This file tracks the implementation against `plans/GO-BACKEND-REWRITE-PLAN.md`.
The migration is in progress. The Go server is not yet a drop-in replacement
for the Rust sensing server and must not be presented as one.

## Implemented in Go

| Area | Current behavior | Evidence |
|---|---|---|
| Process configuration | Validates bind addresses, ports, source names, network exposure, UDP allowlists, filesystem paths, and strict security-related boolean environment values before listeners start. | `internal/config` tests |
| Edge module registry | On-demand catalog fetch, bounded JSON payload, SHA-256 digest, serialized refresh, one-hour TTL, `?refresh=1`, and stale-on-error response. | `internal/edgeregistry` tests and `internal/httpapi` local-upstream integration test |
| HTTP and WebSocket runtime | Health/status API, static UI serving, Rust-shaped node status/CSI freshness responses, mesh-sync REST/metrics, sensing and projected pose/introspection streams, one-use scoped WebSocket tickets and read-only browser-session upgrades, host allowlist, static bearer token, OAuth bearer/browser-session authorization, privacy filtering, stale-state refresh after an input gap without extending the measurement timestamp, graceful shutdown. | `internal/httpapi` and `internal/security` tests |
| UDP ingress and mesh clock state | Bounded UDP datagrams with source allowlist and decoders for CSI, edge-vitals, ADR-063 fused-vitals, feature-state, ADR-110 sync, WASM output, and three validated vendor CSI bridge formats. Per-node sync snapshots, offset, staleness, CSI-rate EMA, sequence-based mesh timestamp recovery for flagged CSI frames, REST endpoints, and Prometheus metrics are exposed. Room classification uses deterministic freshness-weighted voting and Rust-compatible 1.5-second room-level hysteresis; it remains separate from spatial fusion. A bounded refresh loop resolves pending classification and emits stale node state after input stops. WASM latest-event REST and WebSocket contracts are migrated. | `internal/ingest`, `internal/protocol`, `internal/inference`, `internal/state`, and `internal/httpapi` tests |
| Signal state | Bounded per-node CSI history, signal features/classification, stale state, edge-reported counts explicitly marked unverified, non-metric signal-field hotspots, freshness-weighted room classification, room-presence-gated count aggregation, and room-level hysteresis. Uncalibrated heart/breathing rates and uncalibrated mmWave distance are withheld from the public WebSocket event. | `internal/signal`, `internal/state`, and `internal/localize` tests |
| Room calibration lifecycle | Binds a session to a lowercase SHA-256 room digest, sorted source node IDs, a qualifying raw CSI grid, and sequence state; enforces frame, duration, contributor, freshness, cancellation, identity, and reset gates. Persists only a canonical 56-tone mean/variance baseline and receipt atomically. Ground-truth count tuning is persisted and applied to the fresh per-node count-sum fallback. Trust APIs explicitly abstain unless every runtime gate passes; calibrated presence/vitals remain unauthorized because the Go backend does not yet implement the held-out field scorer. | `internal/calibration`, `internal/state`, and `internal/httpapi` tests |
| Spatial multi-sensor CSI fusion | Selects a bounded cohort of fresh raw ESP32 frames, uses mesh-epoch timestamps only when all candidates have valid aligned timestamps within the guard, otherwise labels one consistent host-arrival estimate. Antenna amplitudes are collapsed and resampled to canonical 56 tones, then fused with Rust-compatible cosine-attention weights and normalized weight-entropy output. Node geometry is configured by explicit node ID; independent ESP32 phase is never combined, and the API reports that fusion does not produce localization. | `internal/multistatic`, `internal/config`, `internal/state`, and `internal/httpapi` tests |
| Experimental pose and metric calibration | Optional Go CPU inference loads the repository's 56×20 `pose_v1.safetensors` model, accepts only contiguous raw one-antenna 56-tone CSI from one selected/unambiguous node, and exposes normalized 2D keypoints explicitly as experimental. Six-plus operator ground-truth anchors can fit a model-hash-bound pose-output-to-room transform with leave-one-out error gates; only transform metadata is persisted. The current model lacks a detector/confidence head, supports one pose, has weak benchmark scores, and lacks a reported mean-pose baseline, so the API continues to abstain from person detections and validated metric localization. | `internal/pose`, `internal/localize`, `internal/state`, `internal/config`, and `internal/httpapi` tests |
| Adaptive activity classifier | Loads and atomically persists the Rust-compatible 15-feature JSON classifier; trains deterministic softmax weights from bounded `train_<class>_*.jsonl` recordings; applies a loaded model to new ESP32 CSI frames. Accuracy is in-sample only and is not a validation result. | `internal/adaptive`, `internal/state`, and authenticated HTTP API tests |
| RVF registry and inference | RVF v1 read/validation, list/get/load/unload/delete, model metadata and LoRA profile inspection. Loaded models execute only when they declare the versioned `ruview.activity-softmax.v2` architecture and exact feature/weight schema; those weights classify new raw ESP32 CSI observations. Unknown or untyped RVF weights remain inspectable but inert. Active-model status exposes inference availability, validation provenance, frame count, and latency. | `internal/model`, `internal/state`, and `internal/httpapi` tests |
| Activity-model training jobs and datasets | Bounded labelled JSONL dataset listing/detail, one cancellable supervised activity-classification job, per-class recording-file holdout, progress/status, and atomic executable RVF export. File-level validation is diagnostic only and does not establish person/session/room-independent generalization. | `internal/adaptive`, `internal/training`, and `internal/httpapi` tests |
| Recordings | Bounded JSONL writer, synthetic watermark, privacy redaction, safe IDs, list/delete, and active recording lifecycle. | `internal/recording` tests |
| OAuth/OIDC | Cognitum PKCE browser flow; ES256 JWT verification against a startup-warmed, bounded JWKS cache; exact client and scope checks; rejects setup/workload tokens; signed HttpOnly/Lax session cookies with duplicate-cookie ambiguity rejection and expiry capped at the verified access token; browser sessions use the OAuth read scope; one-use WebSocket tickets inherit scopes. OAuth config fails startup closed if issuer/JWKS setup is invalid or unavailable. | `internal/oauth` unit/security tests and `internal/httpapi` end-to-end flow test with a local issuer |
| Host Wi-Fi RSSI source | Windows WLAN scan adapter; source provenance is `rssi_derived`, ESP32 wins over Wi-Fi in auto mode, and UI/API explicitly identifies that this is not CSI or metric localization. | `internal/source` parser/runner/platform tests |
| Vendor RF scalar adapters | Descriptor registry for ten providers; bounded decoders for Origin AI derived events, Plume/OpenSync telemetry, Mist, NETGEAR Insight, Electric Imp, RF Solutions, generic Luma/OpenWrt, and Google Nest network-only events. Linksys and WiFiGarden fail closed. REST descriptor/latest/ingest routes retain provider capability and synthetic provenance. These are not complex CSI adapters and are not hardware validated. | `internal/vendor` tests and `internal/httpapi` route tests |
| Vendor CSI and radar | Bounded MTC1 MediaTek, QCS1 Qualcomm, and RAC1 RTL8721Dx CSI bridge parsers with CRC, dimension, payload, enum, bandwidth, and finite-number checks. MediaTek exposes a bounded/fresh/sorted device list, 256-frame/512-KiB per-device ring, frame views, amplitude/RSSI summaries, and a 1Hz five-minute relative activity history with an optional atomically persisted quiet-room floor. A bounded RTR1 RTL8720F radar decoder validates CRC, dimensions, formats, finite values, and metadata, then exposes only aggregate latest summaries. CSI/radar remain separate from person/pose/localization inference; ESP32 retains source priority. These are project bridge formats, not chipset firmware ABIs, and are not hardware validated. | `internal/csivendor`, `internal/radar`, `internal/activity`, UDP ingress, state, and HTTP API tests |
| Vendor cloud polling | Opt-in bounded HTTPS polling for documented Juniper Mist site client stats and configured partner event adapters for NETGEAR Insight, Origin AI, and Plume/OpenSync. Mist uses its documented token scheme and region hosts. NETGEAR requires a partner-approved host/path; Origin and Plume must expose the bounded RuView event envelope. Credentials are resolved from environment-variable references and never returned by status. Pagination/body/time limits, redirect refusal, strict decoding, retry backoff, and atomic latest-snapshot updates are enforced. Raw Plume OVSDB and speculative endpoints are not translated. | `internal/vendor` poller/decoder tests and local HTTP fixtures; no partner-account fixtures |
| RuField signed surface | `/api/field` and `/ws/field` publish RuField v0.1-shaped events with aggregate CSI features and anonymous P2 presence/motion. A persistent per-install Ed25519 key signs the schema-ordered, serde-compatible canonical JSON; signature and privacy projection are checked before publication. Unverified coordinates, identity, numeric vital rates, and raw CSI frames are withheld. A valid signature proves event integrity, not key enrollment or sensing accuracy. | `internal/rufield` tests, canonical serialization fixtures, and HTTP/WebSocket authorization, Origin, privacy, and signature tests |
| MQTT / Home Assistant | Opt-in Paho MQTT publisher with TLS/system trust, custom CA and mTLS support, username/password environment lookup, reconnect, LWT availability, bounded queues, retained HA discovery, refresh, and state-rate limiting. It publishes coarse presence/motion and RSSI only; no unverified count, localization, pose, identity, vitals, or raw CSI. | `internal/mqttbridge` tests plus Compose Mosquitto discovery/state integration test |
| Compatibility responses | Legacy API paths are registered; endpoints whose adapters are still missing report unavailable/abstained states instead of fabricated results. RuField REST and WebSocket routes return signed events and retain bearer/ticket and Origin checks. | `internal/httpapi` tests; path registration does not establish full method/schema parity |

## Not yet migrated

| Area | Current limitation | Required next work |
|---|---|---|
| Source selection | `esp32` UDP ingress is implemented. `auto` serves labeled synthetic fallback until live input and prefers ESP32 over the Windows-only host RSSI adapter. Linux Docker cannot access the host WLAN scanner. | Validate on Windows with a host scan and physical ESP32; preserve distinct CSI/RSSI provenance. |
| Localization and pose acceptance | Optional single-person image-space pose inference and a calibrated pose-output transform are implemented, but neither model output nor transform establishes a person detection. There is no multi-person detector; the generic track associator is not connected to a live detection source. The shipped model's reported PCK@20 is 3.0% and PCK@50 is 18.5%, and its benchmark omits the mean-pose baseline required for acceptance. `person_localization`, refined pose, and multi-person claims remain unavailable. | Select/train a detector and metric localization model with real CSI/ground-truth data; report a mean-pose baseline and leakage-free held-out metrics; validate on real hardware before enabling person outputs. |
| Pose/model training | The Go job API currently supports supervised activity classification only. Contrastive pretraining, pose-model training, base-model fine-tuning, and LoRA training return explicit `501` responses; there is no Go pose-training job or pose artifact export. The shipped pose weights use a separate experimental inference path and do not provide validated person localization. | Define and port a specific pose architecture, labelled dataset contract, cancellation-safe training lifecycle, and leakage-resistant evaluation before exposing pose training. Never treat activity labels or file-level holdout accuracy as pose evidence. |
| Calibrated localization and trust inference | The Go calibration lifecycle and safe aggregate baseline persistence are available, but the baseline is not yet connected to the Rust eigenvalue/holdout scorer. It cannot authorize occupancy evidence, metric localization, pose, heart rate, or breathing rate. Bootstrap promotion/refinement and calibrated multi-person localization remain unavailable. The dedup factor only affects the per-node count-sum fallback; spatial CSI fusion is an uncalibrated signal product, not a person estimate. | Port and validate the held-out field scorer and bootstrap validation/refinement, then integrate only its calibrated evidence into room-count inference. Keep public trust fail-closed until leakage-free held-out evidence passes. |
| Live vendor integrations | Mist has a documented API poller. NETGEAR, Origin AI, and Plume/OpenSync require partner-specific, configured northbound endpoints; no partner-account fixtures are available. Other decoded vendors (including Electric Imp, RF Solutions, Luma/OpenWrt, and Google Nest) remain ingest-only. | Validate configured partner contracts and response schemas against provider accounts before claiming live deployment support. |
| ESP32 mesh/WASM | ADR-110 sync snapshots/metrics, frame-flag-gated sequence timestamp recovery, synchronized multistatic amplitude fusion, node-ID-keyed geometry, and fusion status APIs are migrated. WASM event decoding, latest snapshot, and WebSocket event broadcast are migrated. The fuser withholds cross-node phase for independent clocks and does not output person locations. | Validate timestamp and spatial behavior on real hardware and leakage-free labeled room data; port/reselect the calibrated scorer before deriving person counts, locations, or pose. |
| Other integrations | Signed, anonymous P2 RuField REST/WebSocket output, privacy-limited MQTT/Home Assistant publishing, non-loopback mDNS DNS-SD discovery, and opt-in OTLP/gRPC log export are available. mDNS is disabled by default in Compose because bridge networking does not forward LAN multicast. Separate Homecore and Matter products remain outside this sensing-server migration. | Validate mDNS on a native LAN deployment and OTLP against the target collector; neither feature is a sensing or localization capability. |
| Runtime cutover | A Go multi-stage image and an isolated migration Compose runtime now build and pass an HTTP/UI health smoke test. The repository's main Compose still builds the Rust runtime (and separate Python alternative); Go is not the default. | Complete feature/API parity and acceptance, then switch the sensing service in the main Compose and CI without removing companion products. |

## Validation to date

The latest `docker compose -f backend/docker-compose.test.yml run --rm go-backend-tests`
run formatted the Go tree and passed `go test -mod=readonly ./...` inside the
pinned Go container. The RVF/training slice also passed
`go test -mod=readonly -race ./...`,
`go vet -mod=readonly ./...`, and `go mod verify` in Docker. The production image
build and an isolated loopback runtime smoke check passed; no physical ESP32 or
pose-quality validation was performed. OAuth tests include a regression check
that browser sessions cannot outlive their verified access token. All CSI, vitals, sync, WASM,
vendor CSI, radar, and scalar vendor parser fuzz targets passed bounded runs; the
server binary built in the test container. The latest production image built
through Compose; its smoke container returned healthy `/health/live`, accurate
authorized `/api/v1/info`, an empty adaptive-model status, an empty radar
snapshot, and HTTP 401 for an unauthenticated API request. The latest image was
rebuilt after the OAuth session-expiry fix and smoke-checked: `/health/live` was
healthy, `/api/v1/info` returned 401 without a token and Go capability metadata
with the static token, and `/oauth/status` reported OAuth disabled. The smoke
container was stopped after validation. No Go SDK or Go dependencies were
installed on the Windows host.
Packet/parser and vendor API tests use synthetic fixtures only. These results
are not evidence from an ESP32, a vendor cloud account, or a Rust-vs-Go
differential CSI replay. Adaptive classifier accuracy is in-sample only and
does not establish held-out detection accuracy. Full API/WS schema parity,
Docker production cutover, and browser runtime checks remain separate
validation gates.

Pose/localization verification on 2026-10-10 passed `go test -mod=readonly ./...`,
`go test -mod=readonly -race ./...`, `go vet -mod=readonly ./...`, and `go mod
verify` in the Docker Go container. The runtime image built with the real
repository pose artifact. An isolated, network-disabled smoke container loaded
that artifact, consumed synthetic CSI, returned normalized-image keypoints, and
reported zero person detections plus unavailable metric localization. This is
runtime wiring evidence only; it is not hardware validation or a pose-accuracy
result. No Go toolchain or Go module dependencies were installed on the host.
